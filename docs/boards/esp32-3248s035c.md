# Sunton ESP32-3248S035C

The default `esp32-3248s035c` target supports the classic ESP32 board with a
3.5-inch ST7796 SPI display and GT911 capacitive touch. It uses 480×320 landscape
LVGL, 4 MB flash, DIO at 40 MHz, and internal RAM; PSRAM is not required.
The `R` board with resistive XPT2046 touch requires a different driver.

## Build and install

```sh
pio run -e esp32-3248s035c
pio run -e esp32-3248s035c -t upload --upload-port /dev/ttyUSB0
pio run -e esp32-3248s035c -t uploadfs --upload-port /dev/ttyUSB0
pio device monitor --port /dev/ttyUSB0 --baud 115200
```

Replace the port with the board's CH340 USB–UART port. `uploadfs` installs
`data/index.html`; uploading the application alone does not install the web UI.
If upload cannot enter the bootloader, hold BOOT while pressing RESET, release
RESET, then release BOOT after the upload connects. Use the existing
`scripts/serial_monitor.py` if a serial monitor holds the board in reset.

PlatformIO is the supported build entry point for this repository. It installs
the pinned Arduino ESP32 2.0.17 framework and passes the board setup to every
TFT_eSPI source file. No edits to the installed TFT_eSPI library are needed.

On first boot, join `LDGConfig` (password `configure`) and open the HTTP setup
portal at `http://192.168.4.1/`. The console should report `Display: Sunton ST7796 480x320
ready` and `Touch: GT911 ready at 0x5d` (or `0x14`). A missing GT911 is reported
and probed again once per second. Display initialization occurs before WiFi
setup, so the local UI remains available while the portal runs.
TLS is disabled by default. Add `-DTLS_ENABLED=1` to this target's build flags
to use HTTPS on port 443 instead; see [Optional TLS](../../README.md#optional-tls).

## Tuner connection

| Signal | Sunton GPIO | Connection |
|---|---|---|
| UART2 RX | 35, P3 | Tuner TX, mini-DIN **4**, through 5 V → 3.3 V level conversion |
| UART2 TX | 22, P3 | Tuner RX, mini-DIN **3**, through a suitable TTL level interface |
| Ground | GND, P3 | Tuner mini-DIN **2** / interface common ground |

The [soldering guide](../../WIRING.md#01-тюнер-и-согласование-uart) shows
the buffer circuit and all connections. Mini-DIN **1 carries +12 V**; leave
it disconnected and insulated. For that circuit, take 3.3 V for U1 from the
**V3.3 contact on CN1**, verifying its position on your board; P3 has no 3.3 V rail.

Use the GPIO labels and check the connector orientation on your board. GPIO35
is input-only and has no internal pull-up. The P1 connector labelled TX/RX is
UART0, shared with CH340 programming/diagnostics; it is not the tuner port.
GPIO16/17 are used by the RGB LED and are not assigned to the tuner.

The tuner protocol is 38400 baud, 8N1, 5 V TTL. ESP32 inputs are **not 5 V
tolerant**: do not connect the tuner's 5 V TX directly to GPIO35. Power the board
from regulated **5 V** (USB or its power input; a 5 V / 1 A supply is specified
by the board documentation). Do not connect the tuner's 12 V feed to Sunton.
Use the [tuner connector pinout](../../WIRING.md) to identify signals; an S-Video
cable is not a substitute for a verified tuner cable.

## Onboard pins

| Peripheral | GPIO |
|---|---|
| ST7796 SCLK / MOSI / MISO | 14 / 13 / 12, HSPI at 40 MHz |
| ST7796 CS / DC / RESET | 15 / 2 / shared board reset |
| Backlight | 27, active high |
| GT911 SDA / SCL / RESET | 33 / 32 / 25, I2C at 100 kHz |
| GT911 INT | Not used or driven |
| microSD CS / SCLK / MISO / MOSI | 5 / 18 / 19 / 23; card deselected |
| RGB LED | 4 / 16 / 17; active low, turned off |
| Light sensor | 34 |
| USB–UART TX / RX | 1 / 3 |

Some stock revisions connect GT911 INT to ground. The driver polls over I2C,
resets only through GPIO25, and probes both `0x5d` and `0x14`. It reads and
acknowledges GT911 reports, rejects multi-touch and out-of-range coordinates,
and releases stale input after 100 ms or immediately on an I2C error.
The portrait coordinates are mapped as `x = raw_y`, `y = 319 - raw_x` for
TFT_eSPI rotation 1 (ST7796 MADCTL `MV`): the panel's raw X runs in the
opposite direction to landscape screen Y. Rotation 7 adds `MY` and mirrors
the landscape image horizontally. Resistive calibration is unused.

GPIO34 already measures light. The optional PSU ADC is disabled in this
profile (`VOLTAGE_SENSE_PIN = -1`); set the actual tuner PSU voltage in web
settings for the meter calculation.

## Display rendering

The synchronous SPI flush uses one 10-line LVGL buffer (9600 bytes), replacing
two 5-line buffers with the same total storage. Scale ticks and SWR curves are
cached when the meter size changes; needle endpoints and SWR text are updated
only when their values change. Repeated telemetry with unchanged values does
not invalidate the meter, band, mode or antenna labels. No PSRAM or full-screen
framebuffer is required.

## Flash layout and release files

The existing `partitions_custom.csv` fits in 4 MB and keeps two 1792 KiB app
slots for OTA, a 384 KiB LittleFS partition, NVS and coredump storage.
The build must fit within the app slot; a larger flash layout is not assumed.

| File | Flash offset |
|---|---|
| `bootloader.bin` | `0x1000` |
| `partitions.bin` | `0x8000` |
| `boot_app0.bin` | `0xe000` |
| `firmware.bin` | `0x10000` |
| `littlefs.bin` | `0x390000` |

CI includes the `3248s035c` release binaries and a dedicated Web Flasher entry.
These are separate image parts, not a merged image to write at address zero.

## Tests

Run `pio test -e native` for GT911 probing, register transactions, landscape
coordinates, release/multi-touch handling, short reads, failed acknowledgements,
stale input and timer rollover. Build the Sunton, BTT display and headless targets
to catch integration regressions; `pio run -e esp32-3248s035c -t buildfs` checks
the filesystem image.
