# MQTT and Home Assistant

## Connection

Enter the broker hostname, port and optional login in **Settings → MQTT**.
An empty broker disables MQTT. Blank password on save keeps the stored value.
The header opens connection diagnostics, including attempts, retry delay and
last error. **Reconnect** requests a new session without rebooting.

Client ID is `ldg-tuner-<mac>` and base topic is `ldg/tuner/<mac>`, using the
full 12-digit lowercase Wi-Fi MAC without separators. Settings and
`GET /api/config` expose `mqttBaseTopic`. Each board has independent topics.

Port **8883** enables TLS with hostname and certificate verification. Time
synchronization must complete before connecting. The included CA bundle trusts
Let's Encrypt ISRG Root X1/X2; untrusted, expired or wrong-host certificates
fail the connection. There is no plaintext fallback. All other ports use
plaintext MQTT. Web HTTPS is a separate build option.

The Sunton client requests a 4096-byte TLS maximum fragment length. A broker
must support that TLS extension for this profile; an incompatible broker is
reported as a connection error. For custom CAs, see
[MQTT trust anchors](../certs/mqtt/README.md).

### rotator.r3v.ru

Create an LDG device in the cabinet using its Wi-Fi MAC. Copy its generated
server, port **8883**, login and password into MQTT settings. The Client ID is
generated by firmware. Disable Home Assistant discovery for this broker.
The service uses [MQTT API 2](logger-bridge.md) for command context, expiry and
duplicate handling.

## Topics

Paths below are relative to `ldg/tuner/<mac>`.

| Topic | Direction | Payload / retention |
|---|---|---|
| `/status` | Published | `online` / `offline`, retained; Last Will is `offline` |
| `/state` | Published | Active tuner snapshot, retained |
| `/radio/state` | Published | Radio snapshot, retained |
| `/command` | Subscribed | Command JSON, QoS 0, **retain disabled** |
| `/command/response` | Published | Command result, not retained |

Example state fields:

```json
{"fwd_power":250,"ref_power":10,"swr":1.5,"band":"20m","mode":"controlled","tuner_mode":"manual","antenna":"A","source":"local"}
```

`source` is `local` or `remote`. State follows the active tuner, including
commands. A remote timeout falls back to local telemetry after three seconds;
a running remote command keeps its recipient and is never redirected locally.

The MQTT snapshot keeps the last valid FWD, REF, SWR and band individually.
`held` identifies retained measurements; `telemetry_fresh` reports live data.
Measured zero replaces a previous power reading; unknown SWR keeps its last
valid value. Before the first reading it is unknown. A source change or reboot
clears this in-memory history. Local antenna and mode retain acknowledged state
when RF telemetry goes quiet; the serial protocol cannot read front-panel changes.

State is published once per second while tuner measurements are fresh,
including stable or zero power. When measurements stop, significant changes
are published at most once per second and unchanged state every 30 seconds.
Changes are compared with the last successful publication, so small changes
accumulate.

| Measurement / state | Significant change |
|---|---|
| FWD | At least max(1 W, 1% of previous value) |
| REF | At least max(0.1 W, 1% of previous value) |
| SWR | At least 0.05 |
| Power | Zero/nonzero transition |
| Band, mode, antenna, source or validity | Any change |

Initial connection, reconnect, discovery and completed commands request an
immediate update. Intermediate readings are coalesced. A failed publish does
not advance the timer or baseline. Retained state is historical and must not
be used as fresh RF interlock evidence.

## Commands

```json
{"command":"memory_tune"}
```

Names: `toggle`, `antenna_1`, `antenna_2`, `memory_tune`, `full_tune`, `bypass`,
`auto`, `manual`, `controlled`. Named antenna commands are idempotent when the
current port is confirmed. BYPASS enters bypass; use `auto` to exit it.

Responses include `command` and `result`: `success`, `failed`, `invalid_json`,
`missing_command` or `unknown_command`. Commands are not automatically retried.
For request IDs, deadlines, context tokens and duplicate protection, use the
[MQTT API 2 contract](logger-bridge.md).

## Home Assistant discovery

Enable discovery for a broker connected to Home Assistant. Firmware publishes
six sensors (forward power, reflected power, SWR, band, mode, antenna) and seven
buttons (antenna toggle, memory tune, full tune, bypass, auto, manual, controlled).
Availability uses the board's `/status` topic. Entities retain stable IDs across
restarts and firmware variants.

Discovery configurations use
`homeassistant/<sensor|button>/ldg_<mac>/<entity>/config`. They and the current
state are resent after broker reconnect or `homeassistant/status = online`.
Each board subscribes to its own commands and the Home Assistant birth topic.

Turning discovery off removes that board's retained discovery records on its
next broker connection. Keep the broker configured and reachable until cleanup
completes. Switching brokers or disabling MQTT cannot remove records from an
unreachable old broker; remove those records there manually.

Display-to-tuner communication uses HTTP, independently of MQTT. See
[remote-unit setup](remote-unit.md).
