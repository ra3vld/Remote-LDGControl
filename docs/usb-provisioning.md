# USB provisioning API 1

Физическая USB-консоль приложения: 115200 бод, JSON-объект на строку с LF.
Стартовые диагностические сообщения могут появляться между ответами. Ответы
API имеют числовое поле `ldg: 1`; остальные строки следует пропускать.
UART тюнера не используется для этого API.

Клиент посылает `hello` со случайным 32-символьным hex-идентификатором `client`
и положительным числовым `cid`. Устройство возвращает `boot`, `sid`, постоянный
`device_id`, `family: tuner`, роль, профиль, версию, коммит, отпечаток исходников
и возможности собранного приложения. Для следующих запросов нужны те же
`boot` и `sid`; `cid` увеличивается. Смена загрузки или сеанса требует нового
`hello` и чтения настроек перед продолжением записи.

| `op` | Назначение |
|---|---|
| `hello` | Идентификация и открытие USB-сеанса |
| `settings` | Сохранённые Wi-Fi/IP/MQTT, признаки наличия паролей и состояние соединений |
| `apply` | Атомарное сохранение объекта `settings`, ответ `saved` и необходимость `restart` |
| `reboot` | Явный перезапуск после сохранения и контрольного чтения |

В `apply.settings` разрешены `wifiSSID`, `wifiPassword`, `clearWifiPassword`,
`mqttBroker`, `mqttPort`, `mqttUsername`, `mqttPassword`, `clearMqttPassword`,
`mqttDiscoveryEnabled`, `useStaticIP`, `staticIP`, `staticNetmask`,
`staticGateway`, `staticDNS`. Неуказанные параметры сохраняются.
Пустой пароль сохраняет прежнее значение; явный флаг `clear…Password: true`
очищает его. Порт 8883 выбирает проверенный MQTT TLS, другие порты — обычный MQTT.
Пустой `mqttBroker` отключает MQTT. Аппаратные настройки, калибровки, параметры
антенн и TCI через этот API не меняются.

Ответы не содержат сохранённых паролей. `settings.hasWifiPassword` и
`settings.hasMqttPassword` показывают только их наличие. Успешный ответ содержит
`status: 200`, ошибка — `status` и `error`. После `apply` клиент обязан прочитать
`settings`, проверить сохранённые поля и только затем подтверждать доставку
реквизитов внешнему сервису. При сетевом перезапуске нужно дождаться нового
приложения, выполнить `hello` и повторить контрольное чтение.

Максимальная строка запроса и JSON-ответа — 1536 байт. Клиент выполняет запросы
последовательно. Повтор последнего запроса с тем же `cid` должен совпадать
побайтно: устройство возвращает сохранённый ответ без повторного применения.
Изменённое тело с прежним `cid`, старый `cid`, другой `boot` или `sid`
отклоняются. После неопределённого перезапуска нельзя повторять запись вслепую.

Открытый USB-сеанс приостанавливает автоматические операции тюнера короткой
возобновляемой арендой. Клиент поддерживает её чтением `settings` каждые две
секунды и закрывает порт после завершения. Измерения UART продолжают приниматься;
команды тюнеру через API отсутствуют. Запись настроек и перезапуск блокируются
при текущей операции, передаче или TUNE. При обрыве USB аренда прекращается
через пять секунд после последнего обслуженного запроса.
